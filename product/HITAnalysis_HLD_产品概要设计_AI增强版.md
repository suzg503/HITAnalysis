## 一、产品定位与升级目标

### 1.1 产品定位

基于**卫宁健康 WinningBI**运营决策支持系统，打造**AI驱动的医院运营数据决策平台**，实现数据可视化、自助分析、指标管理、目标管控、智能预警、AI问答与AI自动分析的一体化能力。

### 1.2 本次升级目标

| 目标类型 | 具体内容 |
|---------|---------|
| 系统对齐 | 对齐 WinningBI 真实登录/权限/菜单/报表体系（地址：127.0.0.1:16878） |
| AI能力补充 | AI问答、AI自动报表、智能解读、异常预警、智能推荐 |
| 日志模块 | 新增**AI操作日志**模块，实现AI行为全链路审计 |
| 设计完善 | 完善交互、权限、数据口径、部署、安全等细节 |

### 1.3 核心价值主张

- **数据标准化**：统一医院运营指标口径，确保数据一致性
- **自助分析**：降低数据分析门槛，业务人员可自主探索数据
- **AI赋能**：通过AI能力实现自然语言查询、智能解读、自动报告生成
- **合规审计**：完整的操作日志和AI日志，满足医疗合规要求

## 四、AI功能总体规划

### 4.1 AI能力矩阵

| AI功能 | 输入 | 输出 | 应用场景 |
|--------|------|------|----------|
| AI问答 | 自然语言问题 | SQL + 图表 + 解读 | "本月门诊人次多少""哪个科室药占比最高" |
| AI自动报告 | 时间范围 + 报告类型 | 文字总结 + 图表 + 建议 | 月度运营简报、质量分析报告 |
| AI异常预警 | 指标阈值配置 | 预警消息 + 原因分析 | 收入突降、药占比超标、医保超支 |
| AI指标推荐 | 用户角色 + 岗位 | 推荐指标列表 | 院长看板、科室看板、财务看板 |
| AI报表生成 | 自然语言需求描述 | 自动生成报表 | "帮我做一张门诊科室收入排名月报" |

### 4.2 AI问答流程设计

```
用户输入自然语言问题
  ↓
AI意图识别（需求理解阶段）
  - 识别查询对象（门诊人次/收入/药品等）
  - 识别时间范围（本月/近7天/自定义）
  - 识别维度需求（科室/医生/诊断）
  ↓
SQL生成（代码生成阶段）
  - 基于指标知识库生成SQL
  - SQL安全校验（防注入、权限检查）
  ↓
数据查询与可视化（验证测试阶段）
  - 执行SQL获取数据
  - 自动选择图表类型
  - 生成数据可视化
  ↓
智能解读（发布展示阶段）
  - AI生成数据解读文字
  - 突出关键发现和异常
  - 支持追问和下钻
  ↓
记录AI操作日志
  - 记录完整流程各阶段信息
```

## 五、AI操作日志模块概要设计

### 5.1 日志定位

**完整记录AI创建指标、AI问答、AI生成报告的全流程**，支持问题排查、合规审计、AI优化分析。

### 5.2 日志类型

| 日志类型 | 记录内容 | 用途 |
|----------|----------|------|
| AI问答日志 | 用户问题、AI生成的SQL、查询结果、解读内容 | 审计AI回答准确性 |
| AI报告日志 | 报告类型、生成参数、报告内容、生成耗时 | 报告生成追溯 |
| AI预警日志 | 预警触发条件、预警内容、推送记录 | 预警效果评估 |
| AI指标创建日志 | 流程各阶段详情（需求理解→设计→生成→验证→发布） | AI指标创建全链路追踪 |
| AI推荐日志 | 推荐场景、推荐结果、用户反馈 | 推荐算法优化 |

### 5.3 日志核心字段（概要）

```
AI操作日志表（sys_ai_operation_log）
├── log_id：日志ID（唯一标识）
├── user_id：操作用户ID
├── session_id：会话ID
├── operation_type：操作类型（问答/报告/预警/指标创建/推荐）
├── flow_id：流程ID（关联完整流程）
├── step_name：步骤名称
├── input_data：输入数据（JSON）
├── output_data：输出数据（JSON）
├── ai_model：使用的AI模型
├── prompt：发送给AI的Prompt
├── ai_response：AI响应内容
├── confidence_score：AI置信度评分
├── execution_status：执行状态（成功/失败/超时/无数据）
├── start_time：开始时间
├── end_time：结束时间
├── duration_ms：耗时（毫秒）
├── error_message：错误信息
├── ip_address：操作IP
├── department：所属科室
└── created_at：日志创建时间
```

### 5.4 日志功能概要

- **查询功能**：按用户、时间范围、操作类型、关键词筛选
- **导出功能**：支持导出Excel格式
- **审计特性**：日志不可删除、不可篡改
- **统计分析**：AI成功率、平均耗时、常见错误分析
- **流程回放**：支持查看完整AI流程的各步骤详情

## 六、数据权限设计

### 6.1 权限模型

```
用户（User）
  └── 角色（Role）
       └── 权限（Permission）
            ├── 菜单权限：四级菜单访问控制
            ├── 数据权限：科室/病区/病案科室三种维度
            ├── AI功能权限：AI问答/报告/预警/推荐开关
            └── 操作权限：查看/新增/编辑/删除/导出
```

### 6.2 数据范围权限

| 权限级别 | 适用人群 | 数据范围 |
|----------|----------|----------|
| 全院数据 | 院长、数据中心管理员 | 全院所有科室数据 |
| 分院数据 | 分院领导、分院管理员 | 本分院所有科室数据 |
| 科室数据 | 科室主任、科室管理员 | 本科室数据 |
| 个人数据 | 普通用户 | 仅个人相关数据 |

### 6.3 AI功能权限控制

| AI功能 | 权限控制点 |
|--------|-----------|
| AI问答 | 可配置某些角色禁止使用AI问答 |
| AI报告 | 可配置报告生成权限范围 |
| AI预警 | 可配置预警接收权限 |
| AI推荐 | 可配置推荐算法启用开关 |

## 八、非功能需求

### 8.1 性能要求

| 场景 | 响应时间要求 |
|------|-------------|
| 普通报表查询 | < 3秒 |
| 复杂多维分析 | < 5秒 |
| AI问答 | < 5秒（含SQL生成+查询+解读） |

### 8.2 安全要求

- **登录安全**：验证码、登录失败锁定、单点登录跳转
- **数据安全**：敏感数据脱敏展示、传输加密（HTTPS）
- **AI安全**：SQL注入防护、AI输出内容审核、置信度阈值控制
- **日志安全**：操作日志不可篡改、AI日志独立审计

### 8.3 兼容性要求

- 支持对接卫宁健康BI现有数据模型
- 支持Chrome、Edge、Firefox主流浏览器
- 支持移动端BI访问（iOS/Android）
