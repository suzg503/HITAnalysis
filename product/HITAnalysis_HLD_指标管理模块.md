## 1. 模块概述

### 1.1 模块定位

指标管理模块是HITAnalysis平台的**核心数据资产中心**，提供业务指标的统一管理、分类维护、应用配置等功能，是数据分析、报表生成、AI洞察的基础支撑模块。

### 1.2 模块价值

- **数据标准化**：统一定义指标口径、计量单位、数据来源，确保数据一致性
- **资产复用**：指标一次定义、多处应用，避免重复建设
- **权限管控**：精细化控制指标应用范围，保障数据安全
- **AI支撑**：为AI创建指标提供标准化的指标定义和知识库

### 1.3 模块结构

```
指标管理
├── 📂 指标分类管理
│   ├── 分类树维护
│   ├── 分类属性配置
│   └── 分类排序管理
├── 📊 指标库管理
│   ├── 指标列表展示
│   ├── 业务域筛选
│   ├── 指标导入导出
│   └── 批量操作
├── 📝 指标定义
│   ├── 基础信息配置
│   ├── 指标类型定义
│   ├── 业务口径描述
│   └── 状态管理
├── 🎯 指标应用配置
│   ├── 应用列表管理
│   ├── 应用指标关联
│   ├── 权限范围配置
│   └── 应用状态控制
└── 🔍 指标选择器
    ├── 分类浏览
    ├── 关键字搜索
    └── 多选/单选模式
```

## 2. 功能模块概要设计

### 2.1 指标分类管理

#### 功能定位
对指标进行层级分类管理，构建结构化的指标体系。

#### 核心功能
1. **分类树维护**
   - 支持多级分类树结构
   - 分类节点新增、编辑、删除
   - 分类拖拽排序

2. **分类属性配置**
   - 分类名称（中文名称）
   - 分类编码（唯一标识）
   - 分类描述
   - 排序号

3. **分类层级示例**
   ```
   指标分类
   ├── 基础指标（BASE_INDEX）
   ├── 业务指标（BUSINESS_INDEX）
   ├── 衍生指标（DERIVED_INDEX）
   └── 技术指标（TECH_INDEX）
   ```

#### 页面布局
- **左侧**：分类树形结构（支持搜索、折叠展开）
- **右侧**：分类详情列表（分类名称、分类编码、排序、创建时间、操作）

#### 数据模型（概要）
```
指标分类表（metric_category）
├── id：分类ID
├── parent_id：父分类ID
├── category_name：分类名称
├── category_code：分类编码
├── sort_order：排序号
├── description：分类描述
└── created_at：创建时间
```

---

### 2.2 指标库管理

#### 功能定位
统一的指标库，管理全院所有业务指标的生命周期。

#### 核心功能
1. **指标列表展示**
   - 分页列表展示
   - 支持多维度筛选
   - 支持批量操作

2. **业务域筛选**
   - 左侧树形结构：全部、营销域、采购域、财务域、人力域等
   - 点击树节点自动筛选指标列表

3. **筛选条件**
   - 指标名称（模糊搜索）
   - 指标编码（精确/模糊搜索）
   - 指标分类（下拉选择）
   - 状态（启用/停用）

4. **功能按钮**
   - 新增：新增指标定义
   - 删除：批量删除指标
   - 导入：批量导入指标（Excel）
   - 导出：导出指标列表（Excel）

5. **表格列定义**
   - 复选框（批量选择）
   - 序号
   - 指标名称
   - 指标编码
   - 业务域
   - 指标类型
   - 数据类型
   - 状态
   - 创建人
   - 创建时间
   - 操作（编辑、发布、下线、删除）

#### 页面布局
- **左侧**：业务域树形结构（1/4宽度）
- **右侧**：筛选条件 + 功能按钮 + 数据表格 + 分页（3/4宽度）

#### 数据模型（概要）
```
指标表（metric）
├── id：指标ID
├── metric_name：指标名称
├── metric_code：指标编码
├── category_id：指标分类ID
├── business_domain：业务域
├── metric_type：指标类型（原子指标/衍生指标/复合指标）
├── data_type：数据类型（数值/文本/日期）
├── unit：计量单位
├── data_source：数据来源
├── business_definition：业务口径
├── description：指标说明
├── status：状态（草稿/已发布/已下线）
├── created_by：创建人
└── created_at：创建时间
```

### 2.3 指标定义

#### 功能定位
创建和编辑指标的基础属性、业务口径和计算逻辑。

#### 核心功能
1. **基础信息配置**
   - 指标名称（必填）
   - 指标编码（必填，唯一性校验）
   - 指标类型（下拉选择：原子指标/衍生指标/复合指标）
   - 数据类型（下拉选择：数值/文本/日期）
   - 所属主题域（下拉选择：交易域/用户域/商品域等）
   - 计量单位（文本输入）
   - 数据来源（文本输入）

2. **业务定义配置**
   - 业务口径（必填，多行文本）：详细描述指标的计算逻辑、取数范围
   - 指标说明（选填，多行文本）：补充备注信息

3. **状态管理**
   - 状态开关：启用/停用
   - 生命周期：草稿 → 发布 → 下线

#### 页面布局
- **弹窗形式**：模态对话框
- **表单区域**：垂直流布局，必填项标记红色星号
- **操作按钮**：取消、确定

#### 数据校验规则
- 指标名称：长度限制、唯一性校验
- 指标编码：英文+数字+下划线、唯一性校验
- 必填项校验：前端提示 + 后端校验

### 2.4 指标应用配置

#### 功能定位
将指标关联到具体应用场景（如报表、看板、API接口），并配置访问权限。

#### 核心功能
1. **应用列表管理**
   - 应用列表展示
   - 筛选条件：应用名称、应用编码、状态
   - 功能：新增、编辑、删除应用

2. **应用基础信息**
   - 应用名称（必填）
   - 应用类型（下拉选择：报表/看板/API接口）
   - 所属部门（下拉选择）
   - 负责人（选择器）
   - 应用描述（多行文本）

3. **指标关联配置**
   - 从指标库选择指标
   - 支持批量添加指标
   - 展示已关联指标列表
   - 支持移除已关联指标

4. **权限配置**
   - 可见范围（下拉选择：全公司/本部门/指定人员）
   - 可见用户（人员选择器）

5. **应用状态控制**
   - 启用/停用开关
   - 状态字段展示

#### 页面布局
- **列表页**：筛选条件 + 功能按钮 + 数据表格 + 分页
- **新增/编辑页**：
  - 第一部分：基础信息
  - 第二部分：指标配置（表格 + 添加指标按钮）
  - 第三部分：权限配置
  - 底部：取消、确定按钮

#### 数据模型（概要）
```
指标应用表（metric_application）
├── id：应用ID
├── app_name：应用名称
├── app_code：应用编码
├── app_type：应用类型
├── department_id：所属部门ID
├── owner_id：负责人ID
├── description：应用描述
├── visibility_scope：可见范围
├── status：状态（启用/停用）
├── created_by：创建人
└── created_at：创建时间

指标应用关联表（metric_application_relation）
├── id：关联ID
├── application_id：应用ID
├── metric_id：指标ID
└── created_at：关联时间

指标应用权限表（metric_application_permission）
├── id：权限ID
├── application_id：应用ID
├── user_id：用户ID
└── created_at：授权时间
```

### 2.5 指标选择器

#### 功能定位
在创建报表、看板或配置告警时，从指标库中快速选择指标。

#### 核心功能
1. **分类浏览**
   - 左侧分类树：业务指标、系统指标等
   - 点击分类自动筛选右侧列表

2. **搜索功能**
   - 关键字搜索（指标名称）
   - 实时搜索结果更新

3. **指标展示**
   - 表格列：指标名称、指标类型、单位、更新时间
   - 支持单选或多选模式

4. **快捷操作**
   - 操作列"添加"按钮：快速添加单个指标
   - 底部确定按钮：批量添加勾选的指标

#### 页面布局
- **弹窗形式**：模态对话框
- **左侧面板**：搜索框 + 分类树（1/3宽度）
- **右侧面板**：指标列表表格 + 分页（2/3宽度）
- **底部**：取消、确定按钮

#### 交互逻辑
- 单选模式：点击行或"添加"按钮，立即关闭弹窗并返回选中指标
- 多选模式：勾选多个指标，点击"确定"按钮返回选中指标列表

## 3. 核心流程设计

### 3.1 指标创建流程（传统模式）

```
用户点击"新增" 
  → 弹出指标定义表单
  → 填写基础信息（指标名称、编码、类型等）
  → 填写业务口径和指标说明
  → 选择状态（启用/停用）
  → 点击"确定"
  → 前端校验（必填项、格式、唯一性）
  → 后端校验（编码唯一性、权限）
  → 保存到数据库
  → 返回成功提示
  → 刷新指标列表
```

### 3.1.1 AI辅助创建指标流程（新增）

**流程定位**：通过AI自然语言输入，自动生成指标定义，提升指标创建效率。

```
用户点击"AI创建指标"
  → 弹出AI对话界面
  → 用户输入自然语言需求（如："创建一个门诊人次月度汇总指标，按科室统计"）
  ↓
【步骤1：需求理解阶段】（记录AI流程日志）
  → AI识别用户意图
  → 提取关键信息：指标对象（门诊人次）、时间粒度（月度）、统计维度（科室）
  → 生成需求理解结果（JSON格式）
  → 记录日志：input_data（用户原始输入）、output_data（理解结果）、耗时
  ↓
【步骤2：指标设计阶段】（记录AI流程日志）
  → AI生成指标定义
    - 指标名称：门诊人次月度汇总
    - 指标编码：MZ_RS_MONTH_SUM
    - 指标类型：衍生指标
    - 业务口径：统计当月所有门诊挂号人次，按科室汇总
  → AI生成指标建议（数据来源、数据类型、计量单位）
  → 记录日志：input_data（需求理解结果）、output_data（指标定义）、耗时
  ↓
【步骤3：代码生成阶段】（记录AI流程日志）
  → AI生成SQL查询代码
    - 基于指标知识库和表元数据生成SQL
    - SQL示例：
      SELECT 
        dept_name AS 科室,
        COUNT(*) AS 门诊人次
      FROM outpatient_visit
      WHERE visit_date BETWEEN '{start_date}' AND '{end_date}'
      GROUP BY dept_name
  → SQL安全校验（防注入、权限检查）
  → 代码审查（语法检查、性能评估）
  → 记录日志：input_data（指标定义）、output_data（SQL代码、审查结果）、耗时
  ↓
【步骤4：验证测试阶段】（记录AI流程日志）
  → 执行SQL获取测试数据（限制返回100条）
  → AI分析数据质量
    - 数据完整性检查（是否有空值）
    - 数据合理性检查（数值是否在合理范围）
    - 数据趋势检查（是否符合业务规律）
  → AI生成测试报告
  → 记录日志：input_data（SQL代码）、output_data（测试数据、测试报告）、耗时
  ↓
【步骤5：发布上线阶段】（记录AI流程日志）
  → 用户确认指标定义
  → 用户点击"确认创建"
  → 保存指标到指标库
  → 状态标记为"待核对"（需人工审核后发布）
  → 记录日志：input_data（确认信息）、output_data（指标ID、创建时间）、耗时
  ↓
【流程结束】
  → 记录完整流程日志（flow_id、总耗时、最终状态）
  → 返回成功提示
  → 刷新指标列表
  → AI提示：指标已创建，建议人工核对业务口径后发布
```

**异常处理流程**：
```
AI创建过程中发生异常
  → 记录异常日志（错误类型、错误信息、堆栈）
  → 触发告警通知（站内消息/邮件）
  → 用户界面提示失败原因
  → 提供"手动调整"选项（用户可编辑AI生成的定义）
  → 提供"重新生成"选项（AI重新生成指标定义）
```

**AI创建指标日志记录要点**：
- 每个步骤独立记录日志（step_name、step_order）
- 关键数据存储：用户输入、AI理解结果、生成的SQL、测试数据
- 耗时统计：每个步骤耗时、总流程耗时
- 状态追踪：每个步骤状态（成功/失败/跳过）
- 流程关联：通过flow_id关联完整流程的所有步骤日志

### 3.2 指标应用配置流程

```
用户点击"新增应用"
  → 填写应用基础信息（名称、类型、部门、负责人）
  → 点击"添加指标"
  → 弹出指标选择器
  → 选择指标（支持多选）
  → 确认添加
  → 配置权限（可见范围、可见用户）
  → 点击"确定"
  → 保存应用配置 + 指标关联 + 权限配置
  → 返回成功提示
  → 刷新应用列表
```

### 3.3 指标导入导出流程

**导入流程：**
```
用户点击"导入"
  → 下载模板文件
  → 填写指标数据
  → 上传Excel文件
  → 后端解析Excel
  → 数据校验（格式、编码唯一性）
  → 批量插入数据库
  → 返回导入结果（成功数、失败数、失败原因）
```

**导出流程：**
```
用户点击"导出"
  → 根据当前筛选条件查询数据
  → 生成Excel文件
  → 下载到本地
```

## 4. 数据权限设计

### 4.1 权限模型

```
用户（User）
  └── 角色（Role）
       └── 权限（Permission）
            ├── 指标分类：查看/新增/编辑/删除
            ├── 指标库：查看/新增/编辑/删除/导入/导出
            ├── 指标应用：查看/新增/编辑/删除/配置
            └── 权限管理：查看/配置
```

### 4.2 数据范围权限

- **全院数据**：院长、数据中心管理员
- **分院数据**：分院领导、分院数据管理员
- **科室数据**：科室主任、科室数据管理员
- **个人数据**：普通用户

### 4.3 字段级权限

- **敏感字段**：部分用户可见
- **隐藏字段**：前端不展示，后端不返回

## 5. 性能优化设计

### 5.1 查询优化

- **索引优化**：指标名称、指标编码、业务域、状态建立索引
- **分页查询**：所有列表查询必须分页
- **缓存策略**：指标分类树、业务域树缓存（Redis）

### 5.2 导入导出优化

- **批量导入**：使用批量插入（batch insert）
- **异步导出**：大数据量导出使用异步任务
- **文件限制**：单次导入不超过10000条

## 7. 前端交互设计

### 7.1 页面状态管理

- **列表页**：筛选条件、表格数据、分页信息
- **新增/编辑页**：表单数据、校验信息、提交状态
