## 1. 产品概述

### 1.1 产品定位

一款面向医疗行业的**私有化部署 BI 分析平台**，通过"工程师维护的维度指标体系 + 本地化 AI 模型"的组合，实现从"自然语言对话"到"数据报表"的极简转化。

### 1.2 核心价值主张

| 价值点 | 说明 |
|--------|------|
| **极简交互** | 自然语言替代复杂报表配置，降低使用门槛 |
| **绝对安全** | 本地化模型部署，医疗数据不出院 |
| **严谨专业** | 底层维度由工程师管控，AI 仅调用预定义元数据，确保计算逻辑无误 |
| **精细管控** | 支持多机构、按钮级权限控制 |

### 1.3 目标用户

| 角色 | 核心诉求 | 使用频率 |
|------|---------|---------|
| **医院管理者** | 全院运营数据总览、决策支持 | 每日 |
| **医务科主任** | 专项监管（如抗生素使用、医疗质量） | 每周 |
| **科室主任** | 本科室运营数据分析、趋势对比 | 每日 |
| **数据工程师** | 维度/指标维护、元数据管理 | 每月 |
| **系统管理员** | 用户权限配置、系统运维 | 每周 |

### 1.4 竞品分析

| 竞品 | 优势 | 劣势 | 本产品的差异化 |
|------|------|------|---------------|
| Tableau | 可视化能力强、生态完善 | 配置复杂、学习成本高、云端部署 | AI 对话生成报表，零配置门槛 |
| Power BI | 微软生态集成度高 | 云依赖、本地化部署成本高 | 纯私有化 + 本地化 AI |
| FineBI | 国内化、功能全面 | AI 能力弱、灵活性不足 | 工程师管控维度 + AI 调用 |

### 2.2 核心数据流转

**流程1：标准报表查看**
```
用户选择报表 → 权限校验 → 加载报表配置 → 执行数据查询 → 渲染图表 → 用户交互（下钻/筛选/导出）
```

**流程2：AI 报表生成（Text-to-Config）**
```
用户自然语言输入 → AI 语义解析 → 匹配维度/指标库 → 生成图表配置 → 权限校验 → 执行数据查询 → 渲染预览 → 用户调优 → 保存至 AI 目录
```

## 3. 功能需求

### 3.1 模块1：AI 洞察中心

#### 3.1.1 AI 自然语言查询

**功能描述：** 用户通过自然语言描述数据分析需求，AI 解析意图并生成报表。

**用户操作流程：**
1. 用户进入【AI 洞察中心】
2. 在输入框中输入自然语言指令（支持语音输入）
3. AI 解析意图，生成结构化确认信息
4. 用户确认或修改后，生成预览
5. 用户在预览沙盒中进行交互操作
6. 确认无误后保存至 AI 目录

**核心交互原则：**
- AI 在生成报表前，必须**先向用户确认解析结果**（不可直接生成）
- 确认信息需展示：指标名称、维度列表、时间范围、计算逻辑
- 预览状态下支持无限次追问调优
- 预览状态下的报表为临时状态，不持久化存储

**快捷指令模板：**
| 模板类型 | 示例 |
|---------|------|
| 趋势分析 | "查看近半年门诊量趋势" |
| 对比分析 | "对比心内科和呼吸科抗生素使用率" |
| 异常分析 | "找出本月抗生素使用超标的科室" |
| 目标达成 | "心内科本月目标值达成情况" |

#### 3.1.2 预览沙盒

**功能描述：** AI 生成的报表首先进入预览沙盒，用户可在此进行交互操作后再决定是否保存。

**沙盒内功能：**
- **图表类型切换**：表格 / 柱状图 / 折线图 / 饼图
- **维度筛选器**：动态筛选时间、科室、医生等维度
- **下钻操作**：点击图表元素触发下钻（预览模式下支持）
- **追问调优**：通过自然语言继续调整报表（"把柱状图改成折线图" / "再加一个同比对比"）
- **导出**：支持导出当前预览的报表（Excel / PNG）

**沙盒状态说明：**
- 预览状态的报表仅存在于当前会话，未保存时关闭页面即丢失
- 超过 30 分钟未操作的预览会话自动过期

#### 3.1.3 AI 报表保存与管理

**保存流程：**
1. 用户点击【保存报表】
2. 弹出保存对话框，要求输入：
   - 报表名称（必填，默认：AI 生成的建议名称）
   - 选择/新建文件夹（默认：未分类）
   - 设置可见性（私有 / 科室共享 / 院区共享）
3. 保存成功后，报表出现在【AI 洞察中心】的目录树中

**AI 报表生命周期管理：**
- **编辑**：支持修改报表名称、文件夹、可见性（不支持修改报表配置，需重新生成）
- **删除**：支持删除（仅报表所有者或管理员可删除）
- **分享**：通过可见性设置控制分享范围
- **导出**：支持导出为 Excel / PDF / PNG

### 3.2 模块2：标准报表中心

#### 3.2.1 预定义报表浏览

**功能描述：** 展示由数据工程师预配置的官方报表。

**功能点：**
- **目录树导航**：按一级/二级分类展示报表列表
- **搜索**：支持按报表名称、标签搜索
- **收藏**：用户可将常用报表加入收藏夹
- **最近查看**：记录用户最近浏览的报表

#### 3.2.2 报表交互

**功能点：**
- **时间筛选器**：支持快捷选择（本月/上月/本季度/本年度）和自定义时间段
- **同比/环比切换**：报表支持一键切换同比/环比视图
- **目标值对比线**：图表中展示目标值红线，超标自动标红
- **多维筛选**：支持按院区/科室/医生/收费项目等维度筛选
- **导出**：支持导出为 Excel / PDF / PNG

#### 3.2.3 下钻分析

**功能描述：** 从汇总数据逐层深入查看明细数据。

**下钻路径配置：**
- 系统预设常用下钻路径（如：院区 → 科室 → 医生）
- 支持自定义下钻路径（最多 5 级）
- 下钻路径在报表配置时由数据工程师预设

**下钻交互：**
- 点击图表上的数据元素（如柱状图的某个柱子）触发下钻
- 页面顶部显示面包屑导航（全院 > 心内科 > 张医生）
- 支持点击面包屑返回上级
- 下钻过程中可继续叠加筛选条件

### 3.3 模块3：元数据管理

#### 3.3.1 维度维护

**维度定义：** 由数据工程师维护的维度库，用户不可修改。

**维度清单：**

| 维度类型 | 维度名称 | 层级结构 |
|---------|---------|---------|
| **组织维度** | 院区 | 院区（一级） |
| | 科室 | 院区 → 科室（二级） |
| | 医生 | 院区 → 科室 → 医生（三级） |
| **时间维度** | 年度 | 无 |
| | 季度 | 年度 → 季度 |
| | 月度 | 年度 → 月度 |
| | 日 | 年度 → 月度 → 日 |
| | 小时 | 日 → 小时 |
| **业务维度** | 收费大项目 | 无 |
| | 地区 | 无 |
| | 费用类别 | 无 |
| | 人员类别 | 无 |
| | 事件维度 | 无 |
| | 临床项目 | 无 |

**维度维护功能：**
- 新增/编辑/删除维度（仅数据工程师）
- 维护维度值（如科室编码、医生编码）
- 维护维度层级关系（父子关系）
- 维护 AI 语义别名（如"心内科"对应的别名有"心血管内科"、"心脏科"）

#### 3.3.2 指标维护

**指标定义：** 由数据工程师维护的指标库，包含指标的计算公式和语义定义。

**指标分类：**

| 一级目录 | 二级目录 |
|---------|---------|
| 运营决策分析 | 日报分析 |
| | 住院运营分析 |
| | 门诊运营分析 |
| 质量指标分析 | 医疗质量监控 |
| | 药品使用分析 |
| | 感染控制分析 |
| 绩效考核分析 | 科室绩效考核 |
| | 医生个人绩效 |

**指标维护功能：**
- 新增/编辑/删除指标（仅数据工程师）
- 定义指标的计算公式
- 绑定指标可使用的维度
- 设置指标的默认展示单位
- 设置指标的默认展示精度

#### 3.3.3 目标值管理

**功能描述：** 为指标设定目标值，用于达标分析和预警。

**功能点：**
- 为指标设定目标值（可针对特定维度组合设定不同目标值）
- 支持目标值的版本管理（历史目标可追溯）
- 支持目标值的批量导入/导出
- 图表中展示目标值参考线

### 3.4 模块4：权限管理

#### 3.4.1 多机构管理

**组织架构：**
```
医疗集团
  └── 院区 A
  │   └── 内科
  │   │   └── 心内科
  │   │   └── 呼吸科
  │   └── 外科
  │       └── 骨科
  └── 院区 B
      └── ...
```

**机构管理功能：**
- 管理员维护机构树结构
- 支持机构的新增/编辑/停用
- 用户可关联多个机构（兼职场景）

#### 3.4.2 权限控制

**权限控制维度：**

| 维度 | 控制内容 |
|------|---------|
| **数据权限** | 用户可见哪些机构的数据 |
| **菜单权限** | 用户可见哪些菜单/模块 |
| **按钮权限** | 用户可见/可用哪些按钮 |
| **AI 权限** | 用户能否使用 AI 洞察功能 |

**数据权限范围（由管理员配置）：**
- **仅本人**：仅本人创建的数据
- **仅科室**：所属科室的数据
- **仅院区**：所属院区的数据
- **跨院区**：指定院区的数据
- **全部**：集团全部数据

**AI 专项权限：**
- 是否允许使用 AI 洞察功能
- AI 生成报表的可见性控制（私有/科室/院区）
- AI 导出权限

#### 3.4.3 权限继承与临时授权

**权限继承：**
- 角色权限自动继承给该角色下的用户
- 上级机构角色自动包含下级机构的数据权限

**临时授权：**
- 支持用户申请临时数据权限
- 审批流程：用户申请 → 上级审批 → 权限生效
- 临时权限设置有效期，到期自动失效

## 5. 业务规则

### 5.1 数据可见性规则

| 场景 | 规则 |
|------|------|
| **报表查询** | 用户只能查询其数据权限范围内的数据 |
| **AI 生成** | AI 生成的报表数据默认受用户数据权限约束 |
| **跨机构查询** | 受用户权限控制，无权则 AI 拒绝执行并提示 |
| **报表分享** | 分享范围不可超出用户自身数据权限范围 |

### 5.2 AI 交互规则（含决策 D1/D2/D3）

| 场景 | 规则 |
|------|------|
| **技术路线** | **[D1] 采用 Text-to-Config，禁止 AI 直接生成 SQL** |
| **意图确认** | AI 必须展示解析确认信息，用户确认后才执行 |
| **多轮追问** | 追问基于当前会话上下文，可修改任何已确认条件 |
| **预览超时** | 预览会话 30 分钟无操作自动过期 |
| **数据权限校验** | AI 在执行查询前，校验用户是否有权访问目标数据 |
| **跨机构查询** | **[D3] 用户的查询请求涉及多机构时，AI 优先校验用户权限，无权则拒绝并提示"您暂无跨机构查询权限，请联系管理员"** |
| **智能洞察结论** | **[D2] 允许附带，但必须在图表数据下方展示「数据来源」和「计算逻辑」，确保结论可追溯到原始数据** |
| **解析失败** | AI 无法解析时，引导用户补充信息或转人工 |

### 5.3 权限继承规则

| 场景 | 规则 |
|------|------|
| **角色继承** | 新用户加入角色，自动继承角色权限 |
| **机构继承** | 上级机构角色自动包含下级机构数据权限 |
| **临时权限** | 设置有效期，到期自动失效，过期后恢复原有权限 |
| **冲突处理** | 用户自定义权限 > 角色权限 > 默认权限 |

### 5.4 报表生命周期规则

| 状态 | 说明 |
|------|------|
| **预览** | 临时状态，未保存，会话过期即消失 |
| **已保存** | 保存至 AI 目录，可重复使用 |
| **已发布** | 管理员审核后可转入标准报表目录 |
| **已归档** | 不再活跃展示，但可搜索找回 |
| **已删除** | 逻辑删除，保留数据但不可见 |
