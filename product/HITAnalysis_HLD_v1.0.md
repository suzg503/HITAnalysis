## 2. 产品定位与价值

### 2.1 产品定位

**HITAnalysis** 是一款面向医疗行业的**私有化部署 BI 分析平台**，通过"工程师维护的维度指标体系 + 本地化 AI 模型"的组合，实现从"自然语言对话"到"数据报表"的极简转化。

### 2.2 核心价值主张

| 价值维度 | 核心主张 | 实现方式 |
|---------|---------|---------|
| **极简交互** | 自然语言替代复杂报表配置 | AI 语义解析 + Text-to-Config |
| **绝对安全** | 医疗数据不出院 | 本地化模型部署 + 内网隔离 |
| **严谨专业** | 计算逻辑确保无误 | 工程师管控维度 + AI 仅调用预定义元数据 |
| **精细管控** | 按钮级权限控制 | RBAC + ABAC 混合权限模型 |

### 2.3 目标用户画像

| 角色 | 核心诉求 | 使用频率 | 使用场景 |
|------|---------|---------|---------|
| **医院管理者** | 全院运营数据总览、决策支持 | 每日 | 晨会汇报、月度经营分析 |
| **医务科主任** | 专项监管（如抗生素使用、医疗质量） | 每周 | 质控周报、专项检查 |
| **科室主任** | 本科室运营数据分析、趋势对比 | 每日 | 科室晨会、绩效评估 |
| **数据工程师** | 维度/指标维护、元数据管理 | 每月 | 指标更新、新需求配置 |
| **系统管理员** | 用户权限配置、系统运维 | 每周 | 人员变动、权限调整 |

## 5. 数据流概要

### 5.1 核心业务流

#### 流 1：标准报表查看

```
用户 → 选择报表 → 网关路由 → 权限校验 → 加载报表配置
                                                          ↓
返回渲染结果 ← 渲染图表 ← 执行查询 ← 数据权限过滤 ← 生成SQL
         ↓
      下钻/筛选/导出
```

#### 流 2：AI 报表生成 (Text-to-Config)

```
用户 → 自然语言输入 → 权限校验 → AI意图识别 → 实体提取
                                                          ↓
返回洞察预览 ← 生成洞察 ← 执行查询 ← 模板转SQL ← 生成配置JSON
         ↓
      预览沙盒调优 → 保存/丢弃
```

#### 流 3：元数据维护

```
数据工程师 → 维度/指标维护 → 变更同步 → 向量数据库更新
         ↓
      AI知识库更新 → 生效
```

### 5.2 数据分层架构

| 数据层 | 存储引擎 | 数据内容 | 一致性策略 |
|--------|---------|---------|---------|
| **应用数据** | MySQL 8.0 | 用户、权限、报表配置、元数据 | 强一致性 |
| **分析数据** | ClickHouse | 业务数据、指标聚合数据 | 最终一致性 |
| **缓存数据** | Redis 7.x | 会话、热点报表、查询结果 | 最终一致性 |
| **向量数据** | Milvus | 维度/指标向量、业务规则向量 | 最终一致性 |

## 7. AI 架构概要

### 7.1 Text-to-Config 核心模式

```
┌─────────────────────────────────────────────────────────────┐
│                    【用户输入】                                │
│      "查看本月心内科抗生素使用率"                             │
└────────────────────┬────────────────────────────────────────┘
                     ↓
┌────────────────────▼────────────────────────────────────────┐
│                  【语义解析】（LLM）                           │
│            意图识别 → 实体提取 → 槽位填充                    │
└────────────────────┬────────────────────────────────────────┘
                     ↓
┌────────────────────▼────────────────────────────────────────┐
│                  【RAG 知识增强】（Milvus）                   │
│            指标匹配 → 维度匹配 → 规则注入                     │
└────────────────────┬────────────────────────────────────────┘
                     ↓
┌────────────────────▼────────────────────────────────────────┐
│                  【配置生成】（LLM + 规则）                   │
│                       ↓                                      │
│            ┌──────────────────────┐                        │
│            │  {JSON配置}          │                        │
│            │   - intent           │                        │
│            │   - metrics          │                        │
│            │   - dimensions       │                        │
│            │   - time_range       │                        │
│            │   - filters          │                        │
│            └──────────────────────┘                        │
└────────────────────┬────────────────────────────────────────┘
                     ↓
               【用户确认】
                     ↓
┌────────────────────▼────────────────────────────────────────┐
│                  【配置转 SQL】（预定义模板）                  │
│            模板匹配 → SQL生成 → 权限注入                     │
└────────────────────┬────────────────────────────────────────┘
                     ↓
                  【执行查询】
                     ↓
                  【智能洞察】
```

### 7.2 安全策略

| 安全策略 | 实现方式 |
|---------|---------|
| **禁止 AI 生成 SQL** | AI 仅输出 JSON 配置，SQL 由预定义模板引擎生成 |
| **权限注入** | SQL 生成时自动注入权限过滤条件 (org_id IN ...) |
| **双重校验** | AI 层和查询层双重权限校验，确保不绕过 |
| **数据溯源** | 洞察结论附数据和逻辑来源，确保可追溯 |

## 8. 接口概要

### 8.1 接口分层

```
┌─────────────────────────────────────────────────────────────┐
│                      【对外接口】                              │
│   RESTful API / HTTPS / JSON                                │
│   版本：v1，未来可扩展至 v2                                 │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  【AI 洞察接口】                                            │
│   POST   /api/v1/ai/query          ← 自然语言查询          │
│   GET    /api/v1/ai/confirm        ← 确认解析结果          │
│   POST   /api/v1/ai/preview        ← 生成预览              │
│   POST   /api/v1/ai/refine         ← 追问调优              │
│   POST   /api/v1/ai/save           ← 保存报表              │
│                                                              │
│  【标准报表接口】                                           │
│   GET    /api/v1/reports             ← 报表列表            │
│   GET    /api/v1/reports/{id}        ← 报表详情            │
│   POST   /api/v1/reports/{id}/drill  ← 下钻                │
│   POST   /api/v1/reports/{id}/export ← 导出                │
│                                                              │
│  【元数据接口】                                             │
│   GET    /api/v1/metadata/dimensions  ← 维度列表            │
│   GET    /api/v1/metadata/metrics     ← 指标列表            │
│   POST   /api/v1/metadata/targets     ← 目标值设置        │
│                                                              │
│  【权限接口】                                               │
│   GET    /api/v1/auth/permissions      ← 用户权限           │
│   POST   /api/v1/auth/roles            ← 角色配置          │
│   POST   /api/v1/auth/temp-grant       ← 临时授权           │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 8.2 接口设计原则

| 原则 | 说明 |
|------|------|
| **统一响应格式** | `{code, data, message, timestamp}` |
| **分页标准** | `page`, `size`, `sort`, `total` |
| **安全认证** | JWT + OAuth2.0，Authorization 请求头 |
| **错误码规范** | 业务代码 + 状态码，详见 API 文档 |

## 9. 非功能需求概要

### 9.1 性能目标

| 指标 | 目标值 | 评估标准 |
|------|--------|---------|
| AI 意图解析响应 | P95 ≤ 3 秒 | 95% 的请求在 3 秒内返回 |
| 报表下钻响应 | P95 ≤ 2 秒 | 95% 的请求在 2 秒内返回 |
| 标准报表加载 | P95 ≤ 2 秒 | 95% 的请求在 2 秒内返回 |
| 并发用户数 | ≥ 100 | 系统稳定支持的并发数 |
| 系统可用性 | ≥ 99.9% | 年度可用率 |

### 9.2 安全与合规

| 维度 | 要求 |
|------|------|
| **数据本地化** | 医疗数据不出院，AI 模型本地化部署 |
| **传输加密** | 全站 HTTPS，TLS 1.3 |
| **身份认证** | JWT + OAuth2.0，15 分钟无操作自动登出 |
| **密码策略** | 8 位以上，含大小写、数字、特殊字符 |
| **审计日志** | 全量操作日志，保留 90 天 |
| **合规要求** | 遵守《数据安全法》《个人信息保护法》 |

### 9.3 可用性目标

| 维度 | 要求 |
|------|------|
| **响应式设计** | 桌面端(1920+)、大屏(3840+)、平板端(1024+) |
| **语音输入** | 医疗场景下支持语音快速输入 |
| **离线降级** | AI 不可用时自动切换至标准报表模式 |
| **错误恢复** | 提供清晰的错误信息和恢复指引 |

## 10. 实施路线概要

### 10.1 迭代规划

| 阶段 | 周期 | 交付内容 | 关键里程碑 |
|------|------|---------|-----------|
| **MVP** | 6 周 | AI 洞察中心（基础）、标准报表查看、权限管理基础版 | 内部测试可用 |
| **V1.0** | +4 周 | 下钻分析、同比/环比、目标值管理、报表导出 | 生产环境上线 |
| **V1.1** | +4 周 | 元数据管理完善、语音输入、移动端适配 | 全平台适配 |
| **V1.2** | +4 周 | 数据预警、报表订阅、数据大屏 | 功能完善 |

### 10.2 风险预控

| 风险 | 应对策略 |
|------|---------|
| **LLM 准确率不达标** | 持续优化 Prompt、引入人工审核机制、兜底方案 |
| **跨机构权限漏洞** | 双重校验、全量审计日志、定期安全审计 |
| **AI 服务不可用** | 自动降级为标准报表模式，确保核心业务不中断 |
| **数据同步延迟** | CDC 实时同步、数据质量监控 |
